## How to Contribute

All contributions, feedback, bug reports, and suggestions are directly reviewed and managed by **Muthumanikandan B**.

### 1. Reporting Bugs & Issues
- Before opening a new issue, check existing open issues to avoid duplicates.
- Provide clear steps to reproduce the issue, your device / OS version (Android / Windows), app version, and relevant logs if available.
- Submit bug reports via the [GitHub Issues](https://github.com/muthumanikandanb2005-ux/PulseMusic/issues) page.

### 2. Feature Requests & Proposals
- Have an idea to make Pulse Music even better? Open an issue with the tag `enhancement` and describe your idea, potential use cases, and how it aligns with Pulse Music's design principles.

### 3. Submitting Pull Requests (PRs)
1. **Fork & Branch**:
   ```bash
   git clone https://github.com/muthumanikandanb2005-ux/PulseMusic.git
   cd PulseMusic
   git checkout -b feature/your-feature-name
   ```
2. **Code Standards**:
   - Follow Kotlin and Compose Multiplatform idioms and conventions.
   - Maintain consistent formatting using Kotlin ktlint (`./gradlew ktlintCheck`).
   - Ensure the app compiles cleanly on both Android (`./gradlew :androidApp:assembleRelease`) and Desktop (`./gradlew :desktopApp:createDistributable`).
3. **Commit Messages**:
   - Write clear, concise commit messages following conventional commits (e.g. `feat: ...`, `fix: ...`, `perf: ...`).
4. **Submit PR**:
   - Push your branch to your fork and submit a Pull Request to `main`.
   - Assign or tag **@muthumanikandanb2005-ux** for review.
